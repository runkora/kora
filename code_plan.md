## 0. Mission, branch discipline, and how to work

**Delivery shape: one PR, authored on `feat/vcluster-design`.** Every change is written and committed on `feat/vcluster-design` and lands in a single PR to `main`, built as dependency-ordered commits (work packages WP-1 … WP-15, one or more commits each) so the branch is reviewable commit-by-commit and bisectable.

**`origin/feat/vcluster` is purely for reference.** It is never checked out, merged, or cherry-picked. Its code is only *read* as the source to port from:

```bash
git fetch origin feat/vcluster                                      # ensure the ref exists locally
git ls-tree -r --name-only origin/feat/vcluster -- <dir>            # list reference files
git show origin/feat/vcluster:<path>                                # read a reference file
git diff main origin/feat/vcluster -- <path>                        # see exactly what the prototype changed
```

Both `feat/vcluster` and `feat/vcluster-design` fork from the same `main` commit (`837b755`), so `git diff main origin/feat/vcluster` is the complete prototype delta (~13,200 insertions across 127 files).

**Porting discipline (preserves ADR decision A3's intent):** default to **verbatim port** of the reference code — it encodes ~two dozen live-debugged constraints that only reproduce on a real cluster. Apply *only* the changes this plan mandates. Do not "improve" ported code beyond the mandate; that is how pinned findings die. Every work package ships the pinned-decision tests for the code it ports **in the same commits**, and commit messages name the WP and the pinned decisions preserved (e.g. `feat(devenv): port reconciler core with steady-state loop fixes [WP-5; pinned #1,#2,#3,#20]`).

**No k3d work.** Verification targets the Orbit instance on the cloud Kubernetes (staging) cluster. Unit tests, `helm template` tests, and `make check` run locally; anything live runs on staging. k3d-only accommodations are dropped, not gated (see §Deviations).

Only two things fall outside the PR: cloud infrastructure work (Track V — not repo changes) and the post-verification cookie-fallback deletion (WP-14, whose gate cannot be satisfied before merge).

**Docs of record (already resolved by the repo owner — do not re-litigate):**
- PRD: `docs/prd/ephemeral-dev-environments.md` on `feat/vcluster-design`. The ADR's references to `ephemeral-dev-environments-new.md` are ignored; WP-1 amends those links.
- Design ADR: `docs/adr/2026-07-13-ephemeral-dev-environments-via-vcluster.md` on `feat/vcluster-design`. The prototype ADR (dated 2026-07-07) stays on `feat/vcluster` as the reference record of the vibe-coded solution — it is **not ported**, and no path to it is checked into this tree since it will not exist once this branch merges to `main`; consult it via `git show origin/feat/vcluster:docs/adr/2026-07-07-ephemeral-development-environments-via-vcluster.md` for the "why" behind every pinned decision.

**Flags to resolve early (ask the repo owner / infra owner):**

## 6. Deviations from the ADR (driven by the cloud-only and single-PR directives — already approved)

1. **A3 "in-place hardening" becomes "port-and-harden per package"** — the substrate is the reference branch's code shapes, ported verbatim-by-default with mandated fixes, instead of a merge followed by refactor. Findings-preservation is enforced by same-commit pinned tests + reference-diff review.
2. **Phase A's k3d verification bed is skipped** — unit/`helm template` tests run locally; live verification happens only on staging (Track V must land early). The ADR's "integration suite green on k3d" exit criterion becomes "green on staging, run from this branch before merge".
3. **CoreDNS split-horizon mirror is not ported** (`ensureInVClusterCoreDNSSplitHorizon` + 5 tests + the CoreDNS-ready install gate in `devenvironment_platform.go`). The ADR said gate it default-off; since k3d is out of scope it's dead code on cloud — resurrect from the reference branch if k3d support is ever needed. `deploy/local/devenvironment.yaml` and `deploy/local/operator-values.yaml` devenv overlays are likewise not ported.
4. **Single-PR delivery** — the ADR's "incremental and shippable per phase" becomes incremental *commits* inside one PR. Consequences accepted: the PR is large (~13k lines), review is commit-by-commit in WP order; nothing ships until everything ships; the one load-bearing ordering (cookie fallback deleted only after live evidence, pinned #14) is honoured by deferring WP-14 post-merge.
